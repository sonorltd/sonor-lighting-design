## What this is
Client-facing **whole-home lighting design configurator** — the lighting counterpart
to the Cinema Aesthetic app (which it is architecturally cloned from). Flow:
**Intro → Plan → Fixtures → LED & Drivers → Circuits & Scenes → Summary**, outputting
a branded **LIGHTING DESIGN PROPOSAL PDF** in the exact seating/cinema-proposal
format (cinema-pdf-luxury system, shared `data/sonor-pdf-luxury.js` root master).

The PLAN derives live from Takeoffs (`takeoffs_floors.content.symbols`, service 04
lighting blocks + LED runs + LC estimate mixes) — **Takeoffs owns the drawing;
this app owns the lighting SPECIFICATION** (products, light levels, circuits,
scenes) and publishes it as `projects.metadata.lighting_spec` (single writer).

Built-in design helpers encode the 2026-08-20 lighting-research pass: lumen-method
lux checks per room (CIBSE-derived residential targets), downlight spacing +
beam-cone geometry, LED strip + driver engineering (80% headroom rule, feed plans,
standard driver sizes), BS 7671 bathroom-zone IP lint, CCT-mix lint, dark-sky
exterior lint, John Cullen three-layer method, scene seeds per room type.

## SSOT
- **`lighting_items`** (Library-owned catalogue, 183 items at birth) read via
  **`v_lighting_catalogue`** — this app never writes catalogue rows. The view
  LEFT JOINs `wq_product_skus` (`library_type='lighting'`) so WeQuote
  cost/sell/labour ride along per item (`wq_sku` / `wq_cost` / `wq_sell` /
  `wq_labour_mins`). Birth catalogue scraped 2026-08-20 from the three trade
  suppliers: **Lighting of London** (83 — lightingoflondon.co, public RRP,
  datasheet + IES per product), **DuraGreen Lighting UK** (61 —
  duragreenlighting.co.uk, trade-only pricing, spec sheets + IES),
  **UltraLEDs** (39 curated — ultraleds.co.uk, strip/profiles/drivers/controls,
  retail inc-VAT pricing). Scrape JSON archives + regeneration notes in
  `reports/LIGHTING-LIBRARY-INTAKE_2026-08-20.md`.
- **`lighting_configs`** — this app's ONLY table writes (mirror of
  `aesthetic_configs`: insert/update, soft-delete via `archived`, never DELETE).
- 4-tier load (Supabase view → localStorage `sonor_lighting_ssot_v1` → bundled
  seed → empty). Bump the cacheKey whenever the adapted shape changes.
  Seed = `data/lighting-catalogue.js`, regenerated by `data/build-seed.sh`.
- **Pricing rule (Bryn 2026-08-20):** WQ sell price wins, public RRP second,
  POA lines "at quotation". DuraGreen trade prices land later via a price-list
  import into `wq_product_skus` — never hand-typed into the catalogue.

## Upstream / downstream
- **Upstream:** Takeoffs (fixture plan), Library (lighting_items curation),
  WeQuote (wq_product_skus pricing), projects (identity + brief).
- **Downstream:** `projects.metadata.lighting_spec` → any consumer (PM brief,
  Engineering, Tender); the proposal PDF → the client.

## Rules
1. Consumer reads views only; NEVER write `lighting_items` or any takeoffs table.
2. Every proposal export mints `SNR-LD-yymmdd-XXXX` and carries it on cover + detail page.
3. Client build gate `window.__LIGHTING_CLIENT__` strips project bar + saved designs + all writes.
4. Version bump = atomic (`/version-bump`); never hand-write `app_versions`.
5. PDF changes: render headlessly + eyeball every affected page before deploy (cinema-pdf-luxury §7).
6. All Takeoffs reads are read-only snapshots — "Pull from Takeoffs" is explicit, never silent overwrite of manual edits (manual rooms survive a re-pull).
